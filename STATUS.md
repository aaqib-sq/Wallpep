# Status

## Current phase

Phase 2 implements a one-shot, on-device portrait cutout and depth-sandwich compositing on top of the Phase 1 photo picker, settings, save/apply flow and visibility-gated, minute-driven live wallpaper. The previous slices rebuilt the UI to the finalized **Obsidian Pulse** look (near-black OLED surfaces, one electric-blue accent `#2563EB`, no gold), replaced the editor with the exact seven-tab structure, added the **My Collection** home screen and trimmed Settings to Preferences, Wallpaper Settings, Memory and About, then turned the five effect areas into **live rendering** and shipped **Auto Rotate**. The current slice ships the **clock animation transition engine** (all 18 Animation Styles play on the clock and date layers) and **per-layer clock/date parallax controls** (see "Transition engine slice" below). CI for the specific commit is the authority for Android assembly, unit tests, lint, privacy checks and the debug APK; no local Android build is claimed.

## Transition engine slice — clock animations play; per-layer parallax (this slice)

- **Entrance transitions render (#150, #151).** The "Enable clock animations" switch and the 18-style "Animation Style" picker in Settings were previously save-only; they now drive a real transition engine in `WallpaperScene`. All 18 reference styles are implemented as pure, unit-tested progress curves in `ClockTransitions` (Fade & Scale, the four Slide … Fade directions, Zoom In/Out, Pop In, Spin In, Rotate In, Swing, Unfold, Glitch, Heartbeat, Drop Bounce, Blur In, Stretch Horizontal/Vertical) and animate the cached clock and date layer bitmaps (translate/scale/rotate around per-style pivots, alpha, `BlurMaskFilter` blur for Blur In, deterministic band-jitter for Glitch). The date trails the clock by a 90 ms stagger; the text layer does not animate.
- **Play moments.** A transition plays (a) when a visible engine receives a *new* effective settings document — the wallpaper-apply / return-to-home moment, an editor save while applied, or an auto-rotate design switch — and (b) on minute rollovers, detected inside `onDraw` from the minute tick, in the applied wallpaper and the editor preview. The first drawn minute after (re)start never auto-animates.
- **Battery discipline kept.** Transitions are bounded wall-timed bursts (450–950 ms by style): the engine re-requests vsync frames only while the scene reports `transitionActive`, the attached editor preview pumps itself with `postOnAnimation` only while running, and every curve ends exactly at rest so the scene returns to the event-driven minute/second/particle cadence immediately after. Hidden engines cancel transition state in `release()`; thumbnails draw the resting scene (`animationsEnabled = false`). With "Enable clock animations" off (the default), nothing changes versus the previous slice.
- **Per-layer parallax (#46, #47, #88, #89).** The Parallax tab's "Clock, Date & Text" sub-tab now carries per-layer **Clock parallax** and **Date parallax** switches plus strength sliders (0–100 %), persisted as additive schema-1 keys (`parallax_clock`, `parallax_clock_strength`, `parallax_date`, `parallax_date_strength`; defaults on/100 %). Semantics: a layer tilts only when the global switch *and* its own switch are on, and its strength is a percentage of the global travel — so documents saved before these keys existed render exactly as before, and the renderer consumes the values through the same `layerShift` path (pure helper `layerParallaxScale`, unit-tested). No new sensor: the existing rotation/gravity listener registration is unchanged and still gated on the global toggles.
- **#45 Clock style remains unrecovered.** The reference inventory records the style-selector field but never recovered its value vocabulary (inline vs stacked rendering is an unconfirmed hypothesis), no DepthX screenshot or DEX artifact exists in this environment, and a web check surfaced only generic marketing copy. No selector was invented; Wallpep's inline and stacked clock formats remain the honest equivalents. Details in `docs/settings-parity.md`.
- **Not started, per the slice brief:** #147 battery % while charging (still save-only; no render path, needs a design decision) and #145/#146 lockscreen/homescreen content gating (still save-only).
- **Verification.** No device or emulator check was possible; CI (assembleDebug + unit tests + lint + privacy guardrails) is the only authority. New unit tests cover the 18 curves' endpoints, ranges and continuity, the glitch hash, `layerParallaxScale` and the new settings defaults/clamps.

## Live engine slice — preview effects render live; auto-rotate cycles (previous slice)

- **Text layer renders.** The editor, the applied wallpaper and thumbnails draw the text layer through the same offscreen-canvas path as the clock: content, saved face, size, letter spacing, alignment, colour/secondary/gradient + angle, opacity, X/Y position, stroke (solid/dashed/dotted, own colour, secondary colour and angle), shadow and the **Show Over Foreground** switch (off = sandwiched behind the cutout like the clock/date with hour-before-minute ordering for the clock itself; on = in front).
- **Transform warps.** Clock/date/text layers each warp around their centre: horizontal stretch, rotation (including 90° steps), four skews (approximated as tangent 2×3 matrices) and the four keystones (perspective X/Y, skew-left-vertical, skew-bottom-horizontal) approximated as projective matrices with a focal length of twice the layer bounds. Cache-friendly: layer bitmaps are re-shaped once per minute (or per second), never per draw.
- **Colorize.** Hue Rotation + Hue (additive, like the reference inventory), Saturation (scaled by Grayscale), Brightness (darken below 100, white-blend above) are folded into one `ColorMatrix` applied to the background (photo or synthetic backdrop) and its scrim, and combined with the foreground darken so the cutout subject shifts with the scene.
- **Parallax.** Wallpaper and layer strengths shift the background/foreground (overscanned ×1.15) and the clock/date/text layers independently. In the editor a transparent drag on the preview (or the full-screen preview) drives the same smoothed tilt; in the live wallpaper the gyroscope (`TYPE_GAME_ROTATION_VECTOR`, falling back to `TYPE_ROTATION_VECTOR`, then `TYPE_GRAVITY`), remapped for display rotation, normalized to ~34° and low-pass filtered, drives it only while visible and only when at least one parallax toggle is on. No permission; no data leaves the device.
- **Particles.** Rain (streaking rain strokes), Snow (wobbled discs) and Sakura (rotated petal paths swaying on a sine) animate at up to ~30 fps in the editor preview and the visible engine; the pool is driven by the count setting (10–200), angle, speed, size, colour and opacity. Thumbnails never animate; hidden engines stop the loop entirely.
- **Clock/date rendering completed.** Gradient fills (0° = left→right, 90° = top→bottom), stroke families under the fill (dash/dot via `DashPathEffect`), shadow family, seconds colour for seconds formats and the stacked hour/minute/second rows all appear in the preview and the applied wallpaper.
- **Auto Rotate.** A new `autoRotateIntervalHours` setting (schema stays 1, additive key `auto_rotate_interval_hours`, clamped 0–168, default **12**, `0` = Off) is editable under Settings → Wallpaper Settings → Auto Rotate Interval (Off/1/3/6/12/24/48 h). The engine cycles the saved collection in **stored (saved) order** — the order designs were saved in the collection document; re-saving a design moves it to the end. Cycling survives reboot via a separate `wallpep_auto_rotate` DataStore (`next_due_at`, `cursor`) in wall-clock time, evaluated at engine start, every minute tick and on settings/collection changes; the active document is never rewritten, so edits are never lost to a rotation. With an empty collection Auto Rotate does nothing — no crash, no placeholder card, home keeps its existing honest empty state. A shared, `settings ===`-identity-cached layer cache keeps the scene cheap to redraw; only a switch of design, minute rollover or particle frame invalidates layers.
- **Still save-only or absent:** battery %, lockscreen/homescreen content gating, the "Hot Trending" chip label (a display name for the local recency sort — it never shows server content), and exact projective math beyond the documented approximations. (Superseded in part: clock animations and the 18 Animation Style transitions now render — see the transition engine slice above.) No device/emulator verification was performed in this environment; CI is the only authority.

- **Home — My Collection.** Logo + "My Collection" heading + a count line, a search field that filters only the user's own saved designs, the four category chips in the granted order (All Wallpapers, Favorited Designs, Hot Trending, Auto Rotate Cycle) and a two-column grid. - **Persistence model.** The active configuration is stored as one versioned JSON document in Preferences DataStore (`settings_json`, schema 1, `SettingsCodec`), and the collection is a JSON array in a second DataStore (`designs`). An unreadable or newer document falls back or blocks saving instead of overwriting.
- **Engine work in this slice.** `WallpaperScene` now renders the chosen clock format (17 formats, including the vertical/stacked rows where hour, minute and seconds each get a line), the chosen date format (8 patterns), left/centre/right alignment anchored on the position sliders, and independent clock/date visibility. ## Model, licensing and privacy

- **Model:** `modnet_photographic_portrait_matting.onnx`, photographic portrait weights, 25,888,640 bytes (24.7 MiB), SHA-256 `07c308cf0fc7e6e8b2065a12ed7fc07e1de8febb7dc7839d7b7f15dd66584df9`. It is committed as an app asset, not downloaded at runtime. The graph was checked and run with synthetic inputs on host CPU; that is not an Android/device test.
- **License:** treat the pretrained weights as **CC BY-NC-SA 4.0, non-commercial**. This is a **personal-use-only app that will never be published as a product or store release**; the model must be reconsidered/replaced if that changes. The upstream repository's general Apache-2.0 statement and a conversion guide's CC BY-NC-SA statement conflict, so this is a conservative restriction, not a claim that the separate weights' provenance has been legally resolved. See [attribution, sources, conflict and checksum](licenses/models/MODNet/NOTICE.md). ONNX Runtime is MIT; its [license](licenses/onnxruntime/LICENSE.txt) is included.
- **Public repository caveat:** this GitHub repository and its pull requests are public. Committing the model and uploading Actions debug artifacts therefore makes those files publicly accessible; “personal use / never published” is the intended use and absence of a product release, not a claim that this repository or APK artifacts are private. Any sharing must respect the applicable attribution, non-commercial and share-alike terms; the conflicting license statements above remain unresolved with the rights holders.
- **Runtime:** `com.microsoft.onnxruntime:onnxruntime-android:1.22.0`, XNNPACK/CPU only. The pinned version's [POSIX provider](https://github.com/microsoft/onnxruntime/blob/v1.22.0/onnxruntime/core/platform/posix/env.cc) uses the [no-op telemetry implementation](https://github.com/microsoft/onnxruntime/blob/v1.22.0/onnxruntime/core/platform/telemetry.cc); Wallpep also sets `ORT_DISABLE_TELEMETRY=1` before runtime initialization and calls `setTelemetry(false)`. Later ORT versions introduced POSIX telemetry, so a runtime upgrade requires a new privacy review. CI checks the selected runtime version, dependency graph, telemetry components, APK model and merged permissions. No ML Kit, MediaPipe Tasks, LiteRT fallback, Play Services segmentation, analytics or network dependency is intentionally included. There is no internet permission. Inference and the model are on-device and designed to work in airplane mode; real airplane-mode operation is still to be checked on the F54.
- **Fallback:** failed/unavailable inference, unsupported native runtime, missing/corrupt foreground or memory pressure leaves the Phase 1 clock/date-over-photo rendering. A completed failure is remembered beside the photo to avoid repeated attempts; choosing the photo again creates a fresh attempt. Interrupted work can be retried on a later start. No personal photos are committed to Git or used in CI.

## Lifecycle and settings

- Each newly picked photo is privately copied and queued for one cutout. An existing saved Phase 1 photo with no sidecar is queued once, non-blocking, when the settings screen opens or a visible wallpaper engine starts. Concurrent engines/activity coalesce the request and one worker bounds concurrent inference; cutouts are never calculated during drawing. The settings screen displays a processing state while work is queued/running.
- Successful transparent PNG cutouts and failure markers live next to their background in `noBackupFilesDir`. Publication is atomic and cleanup removes abandoned sidecars. Normal process death is respected; there is no wake lock, persistent background service, retry timer or sensor.
- Default depth order with a cutout is background, time/date, foreground. The whole-clock switch sets hour and minute together; separate hour/minute controls can differ, and separators/AM–PM follow the minute. The date control is independent. Without a cutout all text stays on top. New preferences are additive to schema 1 and default off for existing installs.
- Independent View + SurfaceHolder/Choreographer engines retain visibility/screen/keyguard guards, minute/event-driven rendering, engine-local bitmap release, cached color notifications and no continuous loop. Existing photo picker, formats, fonts, colors, positions and save/apply semantics remain in place; home-only remains an instructed choice that the public chooser cannot enforce everywhere.
- minSdk 33; compile/target SDK 37.0/37. No stable signing key is present; CI debug signing may require uninstall/reinstall between builds, losing local data.
